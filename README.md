# SHAD ROS 2 — практические задания

В этом репозитории каждое задание находится в отдельной самодостаточной папке.
Нумерация дополнена нулём, чтобы `task01` … `task10` сортировались в порядке курса.

| Задание | Тема | Ветка | Статус |
| --- | --- | --- | --- |
| `task01/` | ROS 2 graph, interfaces and actions · Hidden Gift 2.0 | `master` | Frozen `2026.1-l01-rc2` |
| `task02/` | Workspaces, launch, parameters, QoS and discovery · Black-box graph rescue | `master` | Frozen · проверено в pinned Jazzy image |

## До первого занятия: проверьте Docker

Локально устанавливать ROS 2, Gazebo и Python-пакеты не нужно. Нужны Git,
запущенный Docker и Compose v2 (команда `docker compose`, не
`docker-compose`). Рекомендуется 16 ГБ RAM и 30 ГБ свободного места.

- macOS: установите и запустите
  [Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/).
- Windows: установите
  [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/)
  с WSL 2. Команды курса выполняйте в терминале Ubuntu/WSL, а репозиторий
  клонируйте в `~/`, не в `/mnt/c/`.
- Ubuntu 24.04: установите
  [Docker Engine](https://docs.docker.com/engine/install/ubuntu/) и
  [Compose plugin](https://docs.docker.com/compose/install/linux/). Команды
  курса должны работать без `sudo`. При `permission denied` выполните
  [официальную post-install инструкцию](https://docs.docker.com/engine/install/linux-postinstall/)
  и полностью выйдите и войдите в систему. Членство в группе `docker` даёт
  root-level доступ к компьютеру.

Проверьте установку до занятия:

```bash
git --version
docker version
docker compose version
docker run --rm hello-world
```

До получения личного репозитория можно проверить окружение на общем шаблоне.
Шаблон нужен только для этой проверки: коммиты в него не являются сдачей.

```bash
git clone https://github.com/SHAD-ROS2/tasks.git
cd tasks/task01

# Только Linux/WSL, если id -u выводит не 1000:
export LOCAL_UID="$(id -u)"
export LOCAL_GID="$(id -g)"

docker compose pull
docker compose up -d --wait
./course doctor
```

Откройте IDE: <http://127.0.0.1:8080>, поле робота:
<http://127.0.0.1:8081>. Чтобы войти в контейнер из терминала хоста:

```bash
./course shell
course build
exit
```

После проверки остановите окружение:

```bash
docker compose down
```

## Личный репозиторий и структура курса

Примите приглашение GitHub в private-репозиторий курса и клонируйте именно его:

1. Откройте ссылку из приглашения.
2. Нажмите **Code**, скопируйте HTTPS URL и выполните `git clone <скопированный URL>`.
3. Не публикуйте репозиторий и не переносите решение в общий шаблон.

Один личный репозиторий используется весь курс. Каждое следующее задание будет
добавляться отдельной папкой `task02/`, `task03/` и так далее. Все задания и
решения хранятся в одной ветке `master`; отдельные ветки `l01`, `l02`, `l03`
создавать не нужно. Код каждого задания оставляйте внутри соответствующей папки
`task01/`, `task02/`, `task03/` и так далее.

## Как сдать работу и получить оценку

**От студента требуется только сохранить код решения в уже существующей папке
задания, сделать commit и отправить ветку `master` в свой private-репозиторий.**
Для L01 изменяемые файлы должны остаться внутри `task01/`.

**Commit SHA никуда вписывать и «коммитить» не нужно.** Git создаёт SHA
автоматически после `git commit`. В объявленный дедлайн преподаватель сам
сохраняет идентификатор последнего коммита ветки `master`, который к этому моменту
находится на GitHub, и проверяет именно эту версию. Более поздние коммиты не
меняют уже зафиксированную сдачу, если преподаватель отдельно не подтвердил
пересдачу.

GitHub Actions в личном репозитории даёт только предварительную обратную связь
для тех заданий, для которых опубликован workflow. Для Task 02 источником
локальной проверки служит canonical pipeline из его условия.
После внешней проверки преподаватель создаст или обновит private issue
`L0N: external grading feedback` для соответствующего задания в этом же
репозитории. В issue будут указаны ссылка на проверенный коммит, итоговые баллы
и результаты по критериям. При инфраструктурной ошибке оставьте комментарий в
этой issue и попросите повторно проверить коммит по указанной ссылке.
Источник итоговой оценки — закрытая преподавательская проверка и ведомость, а не
изменяемый workflow или локальный `score.json`.

Если что-то не работает, пришлите преподавателю полный вывод следующих команд,
а также название и версию ОС:

```bash
./course doctor
docker compose ps
docker compose logs --tail=200 workspace
docker version --format '{{.Server.Os}}/{{.Server.Arch}}'
```

## Задание 01

После получения репозитория:

```bash
cd task01
docker compose up -d --wait
./course doctor
```

Полная инструкция находится в `task01/README.md`. Все команды
конкретного задания запускайте из его папки. Workflow в `.github/workflows/`
даёт только формативную обратную связь; итоговая проверка выполняется отдельно.
Git-команды выполняйте на хосте из `task01/`: контейнер монтирует только папку
задания, поэтому встроенный IDE terminal намеренно не видит родительский `.git`.

Перед сдачей заполните `task01/docs/verification.md`: два результата `PASS` или
`FAIL` для `found`/`absent`, одна граница решения и использование LLM (`нет` —
тоже допустимый ответ). Полные логи, Student ID и Commit SHA не нужны. Файл
нужен как краткая запись самопроверки и не даёт отдельных баллов; авто-грейдер
оценивает поведение кода.

Решения, закрытые тесты, roster и преподавательские инструменты в этот репозиторий
не публикуются.

## Задание 02

До доставки задания в личные репозитории повторить показанное на занятии можно
из общего шаблона. Это только учебная копия: изменения и коммиты в ней не
считаются сдачей.

```bash
git clone https://github.com/SHAD-ROS2/tasks.git shad-ros2-tasks-demo
cd shad-ros2-tasks-demo/task02
cp .env.example .env
./course up
./course doctor
./course shell
```

Чтобы показать или редактировать исходники в локальном VS Code, откройте второй
терминал хоста в этой же папке `task02/` и выполните `code .`. Эта папка уже
примонтирована в контейнер как `/workspace`, поэтому изменения видны с обеих
сторон сразу; устанавливать VS Code внутрь контейнера не нужно.

После того как преподаватель добавил `task02/` в ваш личный репозиторий,
используйте те же команды из уже существующей папки:

```bash
cd task02
cp .env.example .env
./course up
./course doctor
./course shell
```

Внутри контейнера выполните clean dependency/build/test pipeline, затем
восстановите single-robot и two-robot launch по внешнему контракту. Полное
условие находится в `task02/docs/Practice_L02.md`; формат отчёта — в
`task02/docs/diagnosis.template.yaml`. Стартовый stack намеренно неисправен, а
публичное условие не перечисляет места внесённых дефектов.

Все изменения Task 02, включая созданный `task02/diagnosis.yaml`, должны остаться
внутри `task02/`. После проверки остановите окружение командой `./course down`,
затем сделайте commit и отправьте ветку `master` из терминала хоста.

Эталонные исправления, staff-only проверки и преподавательские материалы в
student repository не публикуются.

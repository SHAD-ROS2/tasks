# L08. Исправление ошибки в Nav2

**50 минут в парах.** Воспроизведите ошибку сохранения карты, добавьте
регрессионный тест, исправьте причину и подготовьте draft pull request.
Результат должен быть понятен человеку, который впервые открыл ваш PR.

Работаем с учебной копией `nav2_map_server` из Nav2. В ней восстановлена
историческая ошибка #3078. Комплект содержит исходники пакета, маленькую карту
и команды запуска. Для этого опыта достаточно карты и её файлов.
История исходной ошибки и готовое исправление разбираются после взаимного ревью.

## До занятия

Подготовьте Git и Docker. В GitHub сделайте fork учебного репозитория
`SHAD-ROS2/tasks` и клонируйте свой fork. Включите GitHub Actions во вкладке
Actions своего fork. В нём создайте ветку для практики и перейдите в `task08`.

```bash
git switch -c l08-map-repair
cd task08
./lab doctor
./lab prepare
```

Подготовьте окружение до практики. Первый запуск скачивает образ и собирает
два пакета. Во время занятия сборка использует кэш в Docker volume.
Gazebo и графический интерфейс для практики не нужны. Если `doctor` сообщает
о проблеме, сохраните его вывод и покажите преподавателю.

Исходники пакета находятся в `src/nav2_map_server/`.
Существующие unit-тесты работы с картой находятся в
`src/nav2_map_server/test/unit/test_map_io.cpp`.
Все команды ниже выполняются из `task08/`.

## 0–10 минут. Воспроизвести и объяснить симптом

Пользователь сохраняет карту во вложенный каталог. Сохранение завершается
успешно, но повторная загрузка сохранённой карты падает. Карта, сохранённая
в текущий каталог, загружается.

```bash
./lab reproduce
./lab reproduce flat
```

На исходной версии первая команда завершается с кодом 1, а вариант `flat`
проходит. Сохранение успешно в обоих случаях. В первом случае загрузчик
возвращает `INVALID_MAP_DATA` (код 3). Сравните три строки вывода
`YAML image:`, `Image on disk` и `Resolved image`. Каждый прогон работает
в своём временном каталоге в контейнере и убирает его по завершении.
Запишите относительное имя карты и последовательность операций.

Нарисуйте три блока `сохранение → YAML и изображение → загрузка`.
Назовите ожидаемое поведение и сформулируйте одну гипотезу о нарушенном
контракте между записью и чтением.

## 10–30 минут. Тест и исправление

Запустите существующие тесты.

```bash
./lab test
```

Откройте `test/unit/test_map_io.cpp` внутри пакета. Найдите
`MapIOTester.loadSaveValidPGM` и разберите, как он подготавливает карту и
проверяет результат. В `test/unit/CMakeLists.txt` найдите цель `test_map_io`.

Добавьте в существующий набор тест на обнаруженный сценарий. Передайте
сохранению **относительный** путь с вложенным каталогом, затем загрузите
YAML и проверьте содержимое карты. Используйте временный каталог и удаляйте
созданные файлы после проверки. Случай с абсолютным путём в исходном gtest
может пройти и на версии с ошибкой.
Получите ошибку нового теста на исходной реализации и сохраните короткий
фрагмент вывода для PR.

По коду найдите, какой модуль отвечает за нарушенный контракт. Сделайте
небольшое исправление, затем повторите проверки.

```bash
./lab reproduce
./lab reproduce flat
./lab test
./lab compatibility
```

Проверьте три сценария.

- Сохранение и загрузка карты в текущем каталоге.
- Сохранение и загрузка карты во вложенном каталоге.
- Загрузка существующей карты с относительным полем `image` из другого
  рабочего каталога. Путь к самому YAML передайте абсолютный.

Команда `compatibility` загружает поставляемую существующую карту из другого
рабочего каталога. Этот случай проверяет совместимость с уже созданными картами.
Объясните партнёру, какое поведение сохраняет ваше исправление. После
исправления все команды должны завершаться с кодом 0.
Для запуска одного теста доступен фильтр
`./lab test 'MapIOTester.<имя_вашего_теста>'`.

## 30–42 минуты. Подготовить draft PR

Посмотрите diff и проверьте форматирование.

```bash
git diff --check
git diff
```

Добавьте изменённые исходники и тесты в commit, проверьте staged diff
и отправьте свою ветку в fork командой `git push -u origin l08-map-repair`.
Создайте **draft PR внутри своего fork**.
В форме GitHub явно переключите `base repository` на свой fork, выберите
`base: master` и свою ветку в `compare`. У обоих репозиториев в форме должен
быть ваш GitHub login. В заголовке кратко опишите исправленное поведение.

В описании PR укажите следующее.

- Как воспроизвести ошибку и какое поведение ожидалось.
- В чём причина и почему выбранный модуль отвечает за исправление.
- Название добавленного теста и короткий результат до и после исправления.
- Команды проверок и результат проверки существующей карты.

В проверке **Task 08 · Nav2 MapIO** сверяйте SHA проверяемого коммита и ищите
имя своего теста в логе. Если проверка ещё выполняется, приложите локальные
результаты, укажите статус CI и переходите к ревью. Для этой практики
описания изменения в PR достаточно. Обновите документацию, если исправление
меняет обещанное пользователям поведение.

## 42–50 минут. Взаимное ревью

Обменяйтесь PR с другой парой. Ревьюер читает описание, diff и тест,
затем задаёт один конкретный вопрос о совместимости или воспроизводимости.

Проверьте, что новый тест воспроизводит исходный сбой и проходит после
исправления, а изменение находится в модуле, отвечающем за это поведение.
Автор отвечает результатом проверки либо уточняет патч или описание.

К концу практики у пары есть ссылка на draft PR, регрессионный тест,
проверка совместимости и ответ на вопрос ревьюера. На общем разборе сравним
выбранную границу исправления с историей upstream и обсудим перенос
исправления в поддерживаемую ветку.

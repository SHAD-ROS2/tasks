# Windows / WSL: ошибка `bash\r`

Если `./course doctor` выводит `/usr/bin/env: 'bash\r': No such file or directory`,
Windows Git или редактор сохранил скрипт с окончаниями строк CRLF.
В репозитории теперь есть `.gitattributes`: Git будет получать текстовые файлы
с окончаниями LF даже при `core.autocrlf=true`.

## Уже скачанный репозиторий

В терминале Ubuntu/WSL, из папки задания (`task01` или `task02`):

```bash
git pull --ff-only
sed -i 's/\r$//' course
./course doctor
```

`sed` убирает только символ CR в конце строк и сохраняет остальной код, включая
ваши изменения. Если `git pull` сообщает о локальных изменениях или конфликте,
сохраните работу обычным commit и разберите сообщение Git с преподавателем.
Исправление строки через `sed` можно выполнить и до успешного `pull`.

Для Task 01, если такая же ошибка возникает в скриптах внутри `docker/`,
выполните из `task01/`:

```bash
sed -i 's/\r$//' docker/course-internal docker/entrypoint.sh
```

Один `git pull` не всегда переписывает уже существующие файлы, поэтому эта
разовая конвертация может понадобиться после получения `.gitattributes`.
Менять глобальные настройки Git или заново копировать решение не требуется.

## Новые копии и редактирование

Клонируйте репозиторий из терминала Ubuntu/WSL в домашнюю папку `~/`, как описано
в README. `.gitattributes` защищает Git checkout. При сохранении через редактор
выбирайте окончания строк **LF** (в VS Code это переключатель LF/CRLF справа
внизу), если редактор не сохранил формат автоматически.
